Visual search for your LensMemoriae archive. Search for visually similar
photographs by example: paste an image (Ctrl+V) or attach a file, and
the module finds the closest matches using perceptual hashing
(``imagehash``).

Main features:

- Paste from the clipboard or attach a file to search by example
- Finds the source image even when only a part (crop) of it is pasted
- Region-based perceptual-hash index (whole image, tiles and overlapping
  windows)
- Visual Index management screen to monitor and (re)build the hash index
- Manual indexing per image and hashes shown in the image detail view
- Search filters by index state in the Images screen

Configuration
=============

The optional Python package ``imagehash`` (with ``Pillow``) must be
installed in the Odoo environment for visual search to work. In this
Doodba setup add it to the ``PIP_INSTALL_ODOO`` build argument (for
example ``"face_recognition imagehash"``) and rebuild the image. Without
it the module still installs, but no hashes can be computed.

Images must be *downloaded* before they can be indexed (the perceptual
hash is computed from the stored binary). Indexing runs automatically by
cron every 15 minutes on pending images.

Indexed hashes are readable by regular users; only moderators can
(re)build them.

Usage
=====

To search by example:

1. Go to *LensMemoriae > Visual Search*.
2. Paste an image (Ctrl+V), drag & drop one, or click to attach a file.
3. Optionally adjust the similarity threshold (Very close / Similar /
   Flexible) and the maximum number of results.
4. Click **Search**. The closest matches are shown as a grid with a
   similarity percentage. The red box on a thumbnail highlights the
   region of the original photo that matches the pasted part. Click a
   result to open the image record.

To manage the hash index (moderators):

- *LensMemoriae > Visual Index* shows a summary (images with data,
  indexed, pending and errors), a progress bar, and lists images per
  state. Use **Index pending** to build hashes for images still pending
  and **Reindex all** to rebuild everything.
- From an image form, moderators can use the **Index Image** button to
  compute the hashes for that single image, and review the computed
  hashes in the *Visual Search Index* group (state, date, count and the
  list of hashes per region).
- The *Images* screen offers *Visual Indexed* / *Visual Pending* /
  *Visual Index Error* filters.

Known issues / Roadmap
======================

- Detect rotated or mirrored crops (currently only axis-aligned crops
  are recognised; this would need feature matching such as OpenCV/ORB)
- Make the search query scale-invariant across the whole image so
  larger/smaller versions of the same photo match with looser thresholds
- Optimise the similarity scan in SQL (bitwise operators on the stored
  hashes) instead of in Python to support very large archives
- Distinguish exact-duplicate hits from loose regional matches in the
  results UI
- Persist a visual-search history per user
